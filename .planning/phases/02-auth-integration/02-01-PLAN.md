# Plan 02-01: Auth & Session Integration
wave: 1

## Goal
Replace the hardcoded login system in AppContext with Supabase Auth.
Preserve existing Login.tsx UI — only swap the data layer.

## Graphify Analysis
- `ProtectedRoute()` currently reads `user` from AppContext (line 7-10)
- `Login.tsx` calls `login(role, username, password)` from AppContext (line 99-111 of AppContext)
- `AppContext.tsx` stores user in localStorage under `tasklane.state.v2`
- `Sidebar.tsx` reads `user.role` to determine nav items

## Tasks

### 1. Create src/hooks/useAuth.ts
- Wraps `supabase.auth.getSession()` and `supabase.auth.onAuthStateChange()`
- Returns `{ session, profile, loading }`
- Fetches profile from `profiles` table after login to get `role`

### 2. Update AppContext.tsx
- Remove: `seedEmployees`, `seedTasks` imports from seed.ts
- Remove: localStorage full-state sync
- Remove: hardcoded login function
- Keep: `theme` state (localStorage only for theme is fine)
- Keep: `notifications` state temporarily (Phase 5 migrates this)
- Add: delegate `user` to `useAuth` hook
- Add: `login()` calls `supabase.auth.signInWithPassword()`
- Add: `logout()` calls `supabase.auth.signOut()`

### 3. Update ProtectedRoute.tsx
- Check `session` from useAuth instead of AppContext user
- Show loading spinner while `loading === true`
- Redirect to correct login page based on profile role

### 4. Update Login.tsx
- For admin: `supabase.auth.signInWithPassword({ email, password })`
- For employee: same — employees are also Supabase auth users
- Remove role-based credential hint text
